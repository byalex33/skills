# Every X Explained

Produces a finished MP4 + YouTube description in the bold-caps explainer format (reference: Aero Explained, "Every Bankrupt Airline Explained In 10 Minutes"). Topics so far: aviation and WW2.

Read [`references/format.md`](references/format.md) before writing the script or beats: it is the style spec. [`references/beats-format.md`](references/beats-format.md) is the `beats.json` schema; read it before step 5.

## Fixed choices

- Voice: ElevenLabs speech tool (`creative_generate_speech` on the ElevenLabs connector), `voice_id` **`ynTHHllfDmGsZ3G8QJt9`**, `model_id` `eleven_multilingual_v2`, `generations_count: 1`.
- Renderer: Hyperframes, pinned **`hyperframes@0.9.59`**, always with `HYPERFRAMES_SKIP_SKILLS=1` and `--skip-skills` (the user does not want Hyperframes' own skills installed).
- Images: Wikimedia Commons via `scripts/commons.py` (licence + source recorded per file).
- The `brag` plugin is removed; build everything with this skill's scripts.
- Font: **Allo** (SIL OFL 1.1, github.com/joshpuckett/allo), bundled in `assets/fonts/` (Bold, ExtraBold, Black + `OFL.txt`); `build.py` copies it into each project and declares it with `@font-face`. To change weights, add the WOFF2 there and to `FONT_FILES` in `build.py`.

## Layout

One folder per video, default `./videos/<slug>/`:

```
videos/<slug>/
  script.md            the narration, one "## <item>" section per chapter
  beats.json           the edit (step 5)
  audio/chNN.mp3       one voice file per chapter
  audio/narration.mp3  joined voice;  audio/transcript.json  word timings
  assets/              images + manifest.json (licences)
  hf/                  Hyperframes project (generated by build.py)
  <slug>.mp4           final render;  description.txt  title, timestamps, credits
```

`SK=~/.claude/skills/every-x-explained/scripts` below.

## Steps

### 1. Ask the size, then pick the items
First, before any research, ask with the **AskUserQuestion** popup (one call, two questions):
- **How many items?** Options: 6, 8 (Recommended), 10, 12.
- **How long should the video be?** Options: about 5 minutes, about 10 minutes (Recommended), about 15 minutes.
The user may type another number in "Other". Then size the chapters: words per chapter ≈ minutes × 155 ÷ items (this voice reads ~155 words a minute; aim 200–260; under ~120 the chapter shape gets cramped, over ~350 it drags — if the answer falls outside, say so and suggest a better count). Lineup supports up to 12 items (2 rows).

Then choose the items, ordered per `format.md` (strong story first, biggest name last), and a title `Every <X> Explained In <N> Minutes` with N = the chosen length. **Done when** the user approves the list, the order and the title.

### 2. Write the script
Research each item with web search and write `script.md`: one chapter per item, each at the word target from step 1, in the chapter shape from `format.md`. For 6+ items, research in parallel subagents (2 items each) and write the script yourself from their sourced facts. Every date, number and name is checked against a source; keep the source URLs in an HTML comment under each chapter. **Done when** the user approves the script (the voice costs credits, so the script is frozen after this).

### 3. Generate the voice
1. Price it: call the speech tool once with `estimate_only: true` on chapter 1, multiply by the number of chapters, and tell the user the total. Wait for OK.
2. Generate each chapter in its own call (`generations_count: 1`, one `flow_id` for the video). A call that returns is charged: never re-call to retry; report a failure instead.
3. Get each file's `full_res_url` with `creative_get_generations` and `curl` it to `audio/chNN.mp3`.
4. Join and time-stamp:
   ```bash
   cd videos/<slug>/audio
   for f in ch*.mp3; do echo "file '$f'"; done > list.txt
   ffmpeg -y -f concat -safe 0 -i list.txt -c:a libmp3lame -q:a 2 narration.mp3
   HYPERFRAMES_SKIP_SKILLS=1 npx -y hyperframes@0.9.59 transcribe narration.mp3 -d . --language en
   ```
   **Done when** `audio/transcript.json` exists and its word count is within a few percent of `script.md`.

### 4. Get the images
For each item get one **lineup** image, all in one style and facing the same way (text on liveries must not be mirrored, so pick photos that already face right). Either a side-profile drawing on white (search `"<name> profile"`), or a clean in-flight photo cut out with macOS Vision:
```bash
swiftc -O $SK/cutout.swift -o /tmp/cutout   # once; no installs, macOS 14+
/tmp/cutout raw/lu_<id>.jpg assets/lineup_<id>.png   # keeps the largest subject, crops to it
```
In-flight shots against sky cut out cleanly; ground shots pull in trucks, stairs and other planes. Copy the raw photo's manifest entry to `lineup_<id>` (licence carries over). Then the photos the beats need; for many images, write the beat sheet first (step 5) and fetch in parallel subagents (two chapters each, a list of `id: what it shows`); `commons.py` locks the manifest so parallel writes are safe.
```bash
python3 -I $SK/commons.py search "<short query>" --n 8
python3 -I $SK/commons.py get "File:<exact title>" <asset_id> videos/<slug>/assets
```
Keep queries to 2–4 words. Prefer files at least 1200 px wide (`build.py` never upscales, so small files show small). Accurate period markings (e.g. swastikas on WW2 aircraft) are fine: the user wants historical accuracy. Look at every downloaded image (make a contact sheet with ffmpeg) and replace any that is wrong, blurry, watermarked or on a coloured box. **Done when** every image id used in step 5 exists in `assets/` and has a `manifest.json` entry.

### 5. Write `beats.json`
Split the script into beats of about 8 words (lists: one beat per item) and give each a visual, per `beats-format.md` and `format.md`. The `say` strings of all beats, in order, must equal the script word for word. **Done when** `build.py` runs clean (next step).

### 6. Build, check, look
```bash
cd videos/<slug>
[ -d hf ] || HYPERFRAMES_SKIP_SKILLS=1 npx -y hyperframes@0.9.59 init hf --example blank --non-interactive --skip-skills
python3 -I $SK/build.py . hf
cd hf && HYPERFRAMES_SKIP_SKILLS=1 npx -y hyperframes@0.9.59 check
HYPERFRAMES_SKIP_SKILLS=1 npx -y hyperframes@0.9.59 snapshot --frames 40
```
`build.py` prints every beat with its start time; it fails on a missing asset or an alignment that does not increase, and warns under 80% word match or on beats under 0.35 s. The pass rule for `check` is **0 errors**. It still prints "Check failed" because of ~25 Studio-structure warnings (nested clips, track density, duplicate media): those are expected for this one-clip-per-beat design and harmless to the render, so leave them. Tile the snapshot PNGs into a sheet and review them against the checklist at the end of `format.md`. **Done when** the checklist passes on every sampled frame.

### 7. Render and deliver
Run in the background (a full video takes minutes):
```bash
cd videos/<slug>/hf && HYPERFRAMES_SKIP_SKILLS=1 npx -y hyperframes@0.9.59 render -o ../<slug>.mp4 --fps 30
```
Then cut-check the MP4: `ffmpeg … select='gt(scene,0.3)'` cut times should match `build.py`'s beat starts within a frame. Send the user the MP4 and `description.txt`. **Done when** the user has both files.

## Gotchas

- Commons throttles thumbnails at non-standard widths (HTTP 429, minutes per file). `commons.py` snaps `--width` to a standard size (500/960/1280/1920/3840); with that a download takes ~3 s. An original narrower than the asked width also 429s, so `get` drops to the largest standard width below it. Long queries often return nothing. Some subjects have no free photo at all (e.g. Ryanair's founder): use a text card.
- ASR mangles names and numbers; `build.py` aligns by sequence, so a few unmatched words are normal. Under 80% means the audio and script differ.
- A single `snapshot --at` frame can miss a line that a run of nearby frames shows; check a few nearby times before changing code. Frames under 0.2 s into a beat are blank by design (the entrance).
- Emoji are fetched as Twemoji SVGs into `assets/` by `build.py` (no emoji font in the render).
- The first render on a machine spends ~1–2 min on browser setup; later renders of a 48 s slice take ~22 s at 30 fps.
- Motion lives in `build.py` (the `IMG_IN`/`DRIFT`/`TEXT_IN`/`EMPH`/`POP_IN`/`SCENE_IN` tables and `motion()`). Add or tune moves there; use a beat's `motion` field only to override one beat.
